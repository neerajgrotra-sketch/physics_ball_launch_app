# Bank Shot

A bounce-puzzle game. The player launches a steel ball, choosing angle and power, and places a few bars
wherever they like so the ball ricochets into a glass barely wider than itself. **Bounces are true
reflections** off the bars, the glass, the floor and all four board edges (the floor and edges a little softer
than a bar, so a stray ball settles). **A win uses every bar:** all of the level's bars must be placed and the
ball must bounce off each one before it settles in the glass (2 bars, both; 3 bars, all three). Every level is
generated with a stored solution that does.
The last few launch paths stay on screen as fading ghost trails, so each try teaches the next.

Target platform: iOS first, built with Expo (React Native) and @shopify/react-native-skia for the board.
`reference/prototype.html` is the working browser prototype. It is the source of truth for feel,
visuals and controls. Open it in a browser before building any screen. Deliberate differences: the game's
floor and edges bounce (the prototype's are dead), glasses are open with no hood, levels give up to 3 bars,
and the "win uses every bar" rule. The look reference for long multi-bounce chains is a SimLoop clip the owner shared.

## Repo layout

```
physics/      pure TypeScript simulation. No UI imports, ever.
levels/       one JSON file per level, plus index.ts listing them in play order
tools/        design-levels.ts (level geometry source), verify-direct.ts (proof of no direct shot),
              find-solution.ts (finds the Solve answer), report.ts (placement rule: game/placement.ts)
app/          Expo Router screens and components
components/   shared UI (board/ is the Skia board and win card, controls/ the aim sliders and piece tray,
              feedback/ haptics and sound, progress/ the saved level unlocks)
game/         pure game logic (aim, piece tray and drags, unlocks and win text). No UI imports, tested with Vitest
theme/        colour tokens and font names from the prototype, light and dark
assets/       sounds/*.wav and icon.png, generated by scripts/make-sounds.mjs and make-icons.mjs (edit the scripts)
public/       web-only files: index.html template, manifest.json, icons/ (canvaskit.wasm is copied in at build)
reference/    prototype.html, the behaviour and look to match
```

## Rules that must not break

1. **Physics stays pure.** `physics/` must not import React, Expo, Skia, or anything platform-specific.
   No `Math.random`, `Date`, or `performance` inside it. The game, tests and solver all call the same code.
2. **Fixed timestep.** The simulation steps at `DT = 1/240` s, independent of frame rate. The UI never
   steps physics per frame. It calls `simulate()` once per launch, gets the full path, then plays the path
   back at 120 points per second (`recordEvery = 2`).
3. **Determinism is a feature.** The same level, pieces, angle and power must always give the same path.
   Ghost trails and "so close" moments only mean something because of this. The determinism test guards it.
4. **Every level needs the bars, and every level has a stored answer.**
   - Every bar, every time: by rule, in `simulate()` a win needs all of the level's bars placed and touched
     (`skipped` otherwise, with `touched` saying which were hit).
     `findDirectShot()` still sweeps every 0.1 input with no pieces as a guard on that rule.
   - Stored answer: each level JSON has a `solution` (piece positions in whole units, rotation in whole
     degrees, angle and power on the 0.1 grid) that bounces off **every** bar the level gives
     (`usesEveryBar()`). The Solve button places those pieces, sets the values and launches. Tests check
     it is a legal placement, lands, and uses every bar.
   - Never hand-edit level JSON. Change designs in `tools/design-levels.ts` and run it. `findSolution()`
     builds chains bar by bar along the ball's path, then picks the most forgiving launch for one.
5. **Tunnelling.** At 240 Hz and max speed 1120 px/s the ball moves about 4.7 px per step, under its 8 px
   radius. If max speed goes up or the radius goes down, add substeps so the per-step distance stays
   under the radius. The glass tunnelling test catches regressions.

6. **Cross-engine determinism.** iOS runs Hermes, while the tools run on Node (V8). `Math.sin`/`Math.cos`
   can differ in the last bit between engines. Stored solutions are chosen to be forgiving (neighbouring
   0.1 inputs land too), which absorbs this. Still, add an on-device check that runs every level's solution
   in a dev build.

## Coordinates and units

- The world is 400 × 560 logical units (`WORLD`), y pointing down, floor at y = 540, launcher at (44, 512).
  (The prototype is 400 × 720; the game is shorter so the board fills a phone's width under the controls.)
  Scale the board uniformly to fit the screen. Never change world units to fit a device.
- Angle is in degrees (0–90), adjustable in 0.1 steps. Power runs 0–100 and maps to 280–1120 px/s
  through `speedFor()`.
- A placed piece has a centre (x, y), rotation `deg` in whole degrees, and length `len`.

## Gameplay behaviour to match the prototype

- **Aim:** drag out from the launcher. Direction sets the angle and distance sets the power. The −/+
  buttons beside each slider nudge by 0.1.
- **Aim preview:** only the first 0.3 s of free flight is shown, with no bounce prediction. Bounces are
  the puzzle, so never preview them.
- **Pieces:** bars are named Bar 1, 2, 3 (tray chips and board labels). Tap a tray chip to place a bar, drag
  it to move, drag the end handle to rotate. While a bar is selected the aim rows become its rotation
  controls: a 0–179° slider, −/+ 1° nudges (hold to repeat), Remove and Done. Tapping the selected chip
  deselects it. Bars must keep a ball's width (18) from the glass, walls, launcher and each other
  (`game/placement.ts`, the same rule the level generator uses): a bar dragged somewhere it isn't allowed
  turns red and snaps back to its last allowed spot on release; rotation skips clipping angles; a new bar
  lands on the nearest allowed spot. Pieces can't be edited mid-flight. (The prototype removed a bar by re-tapping its chip.)
- **Trails:** keep the last 4 launches, oldest faintest. A successful trail is drawn in red.
- **Skip:** during a flight, a tap on the board (or Launch, which reads "Skip ›") jumps to the end of the
  shot. The path is already computed in full, so the whole trajectory becomes the trail and the outcome
  counts exactly as if watched; only the remaining bounce sounds are dropped (`usePlayback().skip`).
- **Bounces:** bars (restitution 0.85), the glass and its plate, and the floor and four edges
  (`WALL_RESTITUTION` 0.7, with a little friction so a rolling ball stops). A shot ends when the ball
  settles in the glass, comes to rest, hits a dead grey surface if a level has one, or runs out of time
  (14 s). Landing without every bar placed and hit says so and names any bar it missed (`skipNotice`).
- **Dead hits:** when a shot hits a dead surface, mark the spot with a small red ×.
- **Win:** the ball has to settle inside the glass for 0.35 s. Show "In the glass in N tries", then
  unlock the next level and save progress locally.
  After a win, Launch becomes "Watch again ▶": it replays the winning shot exactly (bars restored to where
  they were, same angle and power) without resetting or counting a try. The card's left button is
  "Start over" (or "Try it yourself" after Solve), which resets the level. Any edit after a win (touching the board, a
  bar chip, a slider or rotation) or the card's ✕ closes the card and goes back to normal play, keeping bars,
  trails and tries; the level stays won.
- **Solve:** places the stored solution's pieces (unused pieces go back to the tray), sets angle and power,
  and launches. The win card then reads "Here's one way in", with "Try it yourself" (resets the level) and
  "Next level". The card sits at the top of the board so the solution path stays visible.

## Visual identity

The look is engineering graph paper in light mode and a blueprint in dark mode, with
Barlow and Barlow Condensed type. Use the colour tokens from `reference/prototype.html` (`--paper`,
`--grid`, `--ink`, `--pencil`, `--red`, `--muted`, `--steel`) and follow the system appearance setting.

## Versions and sound

- Version: `package.json` and `app.json` (`expo.version`) stay equal; record changes in `CHANGELOG.md`.
  Store builds bump `expo.ios.buildNumber` / `expo.android.versionCode`. The level list shows the version
  and the git commit (`components/version.ts`; Vercel passes `EXPO_PUBLIC_COMMIT`).
- Music: one looping track per level, mapped in `components/feedback/music.ts` (files in `assets/music`).
  A header ♪ button turns music on/off (remembered). Effects are generated by `scripts/make-sounds.mjs`.
  On web, audio starts on the first tap (browser rule) and runs through one Web Audio context
  (`components/feedback/webAudio.ts`).

## Commands

- `npx vitest run`: physics and level tests. Run them before every commit.
- `npx tsx tools/report.ts`: full no-direct-shot proof plus how forgiving each solution is (about 1 min per level).
- `npx tsx tools/design-levels.ts [id-prefix]`: regenerate level JSON after changing geometry.
- `npx tsc --noEmit`: typecheck.
- `npm run play`: build the static web site and serve it at http://localhost:8090 (stable, fast, deep links work).
- Deployed on Vercel from GitHub (`vercel.json`): every push to `main` rebuilds the site. `public/index.html`
  is the web page template (phone fit, no zoom, Add to Home Screen); `scripts/make-icons.mjs` draws the icons.
- `npm run web`: Expo dev server for working on the web build. `npm run build:web` exports a static site to `dist/`.
  Both first copy `canvaskit.wasm` into `public/`. On web, `index.web.js` loads CanvasKit before the app,
  because Skia binds to it when first imported. Pass style objects, not arrays, to `<Link asChild>` children.

Use Vitest for `physics/` and `tools/`. These modules are pure TypeScript, so they don't need jest-expo.
The unit tests run a coarse 0.5-step version of the no-direct-shot proof. Run `report.ts` before merging any
level or physics change.

## Build order

1. Scaffold the Expo app (TypeScript, Expo Router) around the existing `physics/`, `levels/` and `tools/`.
   Get `vitest` and `tsc` passing before any UI work.
2. Board rendering in Skia: grid, ground, fixed segments, glass, launcher, ball, trails.
3. Launch and path playback with Reanimated, driven by `useFrameCallback`.
4. Aim gesture, sliders, nudge buttons.
5. Piece tray and placement gestures (move and rotate) with react-native-gesture-handler.
6. Win flow, level select, progress saved with AsyncStorage.
7. Haptics on bounce and on landing (expo-haptics), plus sound.
